# Layman's terms

Explain the topic in the arguments. If there is none, re-explain your last reply.
If a reader is named (client, manager, new hire, family), write for them.
Otherwise write for a smart adult with no background in this field.

## Shape of the answer

1. **The point.** One sentence: what it is or what happened.
2. **Why it matters.** One sentence: why this reader should care.
3. **A comparison.** One picture from everyday life, if a good one exists.
   Say where it stops matching if that would mislead.
4. **An example.** Something real: a number, a screen, a person doing a task.
5. **What it means for them.** What changes, what they need to decide,
   or "nothing for you to do."

Skip any step that adds nothing. Short beats complete.

## Writing rules

- Everyday words. "Server" becomes "the computer that runs the website."
- If a technical word must stay because they'll hear it again, explain it
  once in the same sentence and keep using that same word.
- Spell out acronyms or drop them.
- One idea per sentence. Short sentences. Active voice.
- Leave out file names, version numbers, code and internal names unless asked.
- Simplify, but never say something false. Keep any warning that affects
  a decision.
- No filler, hype or padding. Say it once.
- No headings or tables unless the topic truly needs them.

## Before sending, check

- Could the reader follow every sentence without looking anything up?
- Did the first sentence give them the main point?
- Is it shorter than the technical version?
